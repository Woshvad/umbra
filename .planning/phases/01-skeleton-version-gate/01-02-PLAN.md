<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| desk → ledger (SubmitOrder) | A desk submits an order; must not be able to forge another desk's order or read others' orders |
| cross-desk visibility | Daml disclosure (signatory/observer) is the ONLY thing keeping orders/holdings/confirmations private |
| early Clear exercise | The placeholder Clear must fail loudly, never silently "settle" with no effect |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | `Order` / `Venue.SubmitOrder` | mitigate | `Order` signatory = `operator, desk` (both authorities required); created only via `Venue.SubmitOrder` controlled by `desk`, gated by `assertMsg "desk not registered"` |
| T-01-02 | Information disclosure | `Order` / `Asset` / `TradeConfirmation` / `RoundStats` | mitigate | Strict signatory/observer: Order = operator+desk (no observer); Asset = operator+owner; TradeConfirmation = operator + singular desk; RoundStats exposes count only. NO stray observers — a stray observer silently breaks the money shot |
| T-01-03 | Tampering | `Asset` / `Order` quantities | mitigate | `ensure quantity >= 0.0` (Asset), `ensure quantity > 0 && limit > 0.0` (Order), `Split` range check `splitQty > 0.0 && splitQty < quantity` |
| T-01-06 | Tampering | `Round.Clear` placeholder | mitigate | Placeholder body is a loud `assertMsg "Clear not yet implemented (Phase 2)" False`, not a silent no-op — an early exercise fails instead of falsely "succeeding" with no settlement |
</threat_model>
