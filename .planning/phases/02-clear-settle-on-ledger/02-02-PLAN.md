| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-04 | Tampering | partial settlement leaving inconsistent balances | mitigate | All settlement legs live in the single `Clear` `Update` transaction → atomic by construction; any failing leg rolls back the whole thing (SETL-03). Tested by `test_atomicity` (Plan 03). |
| T-02-05 | Tampering | overdraw — a seller settles more than it holds | mitigate | The settlement helper branches on the `Asset.Split` strict `< quantity` boundary and a `> quantity` move hits the Split guard / `ensure quantity >= 0.0` → throws → rollback. |
| T-02-06 | Tampering | settlement creates/destroys value (non-conservation) | mitigate | Conservation is structural — Split/Merge/Reassign archive+recreate preserving total — plus the explicit `Σbuy == Σsell` assert in the body. Asserted globally by `test_settled_balances` (Plan 03). |
