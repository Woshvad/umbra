<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser panel -> JSON API :7575 | Each DeskColumn's DamlLedger carries one desk token; actAs/readAs is the wire-level disclosure filter — a rival's contracts never cross. |
| desk token -> Venue.SubmitOrder | The desk's own token supplies the `controller desk` authority for an in-browser submit; it cannot mint another desk's order. |
| shared RoundStats -> any desk | Observer = desks, so a desk token reads the count — no operator token needed in the browser. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Information disclosure | Faked privacy via render-time filtering | mitigate | Three independent createLedgerContext per desk; each DeskColumn queries with its own token. Live check (Task 3 step 4) inspects the Network tab, not the DOM — B/C data absent from BankA's wire response. |
| T-03-11 | Information disclosure | Wrong ledgerId -> tokens rejected / silent empty panels | mitigate | DAML_LEDGER_ID is one constant; `scripts/verify-privacy.mjs` verifies live BEFORE trusting panels (Pitfall 2). |
| T-03-06 | Elevation of privilege | operator token reaching the browser | mitigate | Only desk tokens imported; center count uses a desk context; grep gate asserts no `tokens.operator` under web/src (D6). |
| T-03-12 | Spoofing | A desk submitting another desk's order | accept (structurally enforced) | Venue.SubmitOrder controller = desk; Order signatory = operator+desk — a desk's token cannot forge another's order (proven on-ledger in Plan 01). |
| T-03-09 | Spoofing | dev JWT reused in a deploy | accept (dev-only) | --allow-insecure-tokens sandbox-ONLY (D5); tokens.json gitignored; documented never-for-deploy. |
</threat_model>
