## Color

Exact palette transcribed from the comp. There is no neutral gray scale — "muted" text is the ink `#0A0A0A` at reduced `opacity` (the comp uses `opacity` and `rgba(10,10,10,…)`, never a separate gray hex). Preserve that technique.

## Per-Party Identity (this is what makes the money shot REAL)

Privacy is **structural at the wire**, not a render-time filter (CONTEXT.md A/PRIV-05). The 3-up is achieved by mounting **one `DamlLedger` provider per column with that desk's own HS256 dev JWT**:

- Three columns each wrapped in their own `<DamlLedger token={tokenFor(deskK)} party={partyId} httpBaseUrl={JSON_API_URL}>` provider (`@daml/react@2.10.4`).
- Each column queries `@daml.js/umbra` `Order` (and `Asset`) **with its own credentials** → it can only ever fetch its own contracts. A rival column literally returns zero `Order` rows → the UI renders the **redaction bars** because there is no data, not because code hid it.
- **Active vs redacted determination:** the column matching the currently-selected party-switch desk is `active` (shows its real order from its own query); the other two are `redacted` (their providers, viewed from the active desk's perspective, return nothing). Implementation note: the comp models this as a single `activeDesk` toggle (lines 681–684, 703–715). Structurally, the cleanest mapping is: the **selected switcher desk = active column shown in full**; the other two columns render the redaction state. The center count reads the **shared `RoundStats.sealedOrderCount`** (a count, observable to all desks per Phase-1 observer shape — comp `sealedCount`).
- Tokens: minted per CONTEXT.md A (Node + `jsonwebtoken`, Daml claim shape, dev secret), written to a frontend-readable `web/src/parties.json` / generated `tokens.json`. Browser holds **only** the 3 desk tokens + `JSON_API_URL` — never the operator's privileged token, never the Anthropic key.

## Responsive / Layout Notes

- The comp is a **fixed desktop composition** (~908px+ artboard in the screenshots; content padded 48px each side). No mobile breakpoints are specified in the comp — **build desktop-first to the comp exactly**; responsive collapse of the 3-up is out of scope (and would undermine the side-by-side money shot). A min content width around the 3-up grid is acceptable.
- Borders are universally `1px solid #0A0A0A`. Never use a softer border color; use opacity for lighter rules (`.18`/`.25`).
- The 3-up grid is `1fr 1fr 1fr` with internal `1px` column borders and `gap:0` — the borders, not gaps, separate columns.
- Exact reference measurements are inlined per-section above (header `22/48/14`, main pad `48`, inner inset `42`, count `108px`, headline `78px`, column pad `24/24/26`).
