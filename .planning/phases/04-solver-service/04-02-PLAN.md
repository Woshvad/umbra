## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| solver (Operator authority) → JSON API :7575 | the only holder of the Operator JWT; exercises Round.Clear |

| T-04-05 | Tampering | submitting an unverified clearing to the ledger | mitigate | `settle` submits ONLY the deterministic `computeClearing` output; `Round.Clear` re-verifies §8 on-ledger (recompute-and-assert, Auction.daml lines 166-189) and rejects any mismatch. No skip-verification path. |
| T-04-06 | Tampering / EoP | double-settle by replaying settle on a recreated Round | mitigate | `Clear`'s on-ledger guard (`status == Closed || Cleared`) rejects a re-exercise on the `Settled` recreate; `settle` re-queries the current cid so it sees the latest status. The 409 user-facing guard is added in the API (Plan 04-03). |
| T-04-07 | Spoofing | hard-coded per-boot party IDs drifting after a sandbox reboot | mitigate | Read `daml/parties.json` fresh (fallback-mint path) and the token's embedded party; never hard-code `hint::<fingerprint>` IDs (D4). |
| T-04-12 | Tampering / DoS | settle on a non-§4 round with split/insufficient holdings passes an undefined cid into Clear | mitigate | Sufficiency predicate on a single holding (A2 scope); on no-match `settle` throws a clean secret-free `insufficient or missing <symbol> holding` error instead of an undefined-cid exercise; A2 documented as a known P4 limitation (auto-merge is stretch). |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan (deps installed in Plan 04-01, all audited [OK]/[SUS-false-positive]). |
