</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (desk token) → Canton participant (JSON Ledger API v2) | the peek issues a REAL cross-party read with the desk's own bearer; the participant is the privacy authority |
| operator credentials → browser | must NEVER cross — the peek uses only per-desk tokens |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-02-PEEK | Information Disclosure (being DISPROVEN) | PeekConsole rival-party query | mitigate | the participant returns `[]`/403 for the desk token — the demo proves the mitigation is structural (Canton per-token active-contracts, ASVS V4) |
| T-08-02-OPTOK | Elevation of Privilege | operator token in browser | mitigate | PeekConsole uses only `tokens[activeDesk]` via httpBaseUrlFor; no operator token/context is imported (grep-clean, threat T-06-01 precedent) |
| T-08-02-BEARER | Information Disclosure | rendering the request's Authorization header | mitigate | elideBearer truncates the token; the full bearer is never rendered (UI-SPEC) |
| T-08-02-NODE | Spoofing | wrong-node read producing a misleading error | mitigate | reuse httpBaseUrlFor(activeDesk) so the query hits the desk's OWN node; a network/CORS error must not masquerade as the empty-privacy result (Pitfall 4) |
</threat_model>
