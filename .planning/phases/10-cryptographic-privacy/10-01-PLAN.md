<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| desk → ledger (commit) | The desk posts a commitment + escrows a bond; untrusted order contents never appear until reveal |
| desk → ledger (reveal) | The desk submits the full order + salt; the ledger recomputes the hash and is the accept/reject authority |
| operator → bond Asset | Operator-custody Asset moves (escrow / return / slash) run under operator authority only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | RevealOrder | mitigate | On-ledger `sha256(toHex(order‖salt)) == commitment` `assertMsg`; the ledger rejects a reveal-different-order (test_reveal_mismatch_rejected) |
| T-10-02 | Repudiation/DoS | commit-then-vanish | mitigate | Bond escrowed at CommitOrder, forfeited to the operator pot by ForfeitBond on non-reveal (test_bond_forfeit) |
| T-10-03 | Info Disclosure | order contents pre-reveal | mitigate | Only `commitment : Text` + bond are on-ledger during the window; contents exist only after a verified reveal |
| T-10-04 | Tampering | non-canonical serialization | mitigate | ONE `commitOf` serializer shared by commit + reveal (fixed field order, explicit Optional tokens, pinned Decimal scale, injective delimiter) — Pitfall 2 |
| T-10-05 | Repudiation | alpha crypto API drift | accept | `DA.Crypto.Text` pinned to SDK 3.4.11, `-Wno-crypto-text-is-alpha` flagged + labeled alpha in DECISIONS.md; a future SDK bump is a documented watch item |
</threat_model>
