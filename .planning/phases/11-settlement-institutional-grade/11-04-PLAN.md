  </read_first>
  <action>
    Create `module Umbra.Settlement`. Define `data Instruction = Instruction with sender : Party;
    receiver : Party; instrument : InstrumentId; amount : Decimal deriving (Eq, Show)`.

    Pure builders (top-level, testable without the ledger):
    - `buildGrossInstructions : Decimal -> [Allocation] -> InstrumentId -> InstrumentId -> [Instruction]`
      — from the verified allocation at p*, derive the gross DvP legs: every Sell desk delivers
      `filledQty` of the BOND instrument to the buyer(s); each buyer pays `filledQty * p*` of the
      CASH instrument. Generalize the current single-buyer fold to N buyers × M sellers (a uniform
      price means the cash owed per unit is identical, so pair matched buy units against sell units
      deterministically — document the pairing rule; the KEY invariant that matters is
      per-instrument conservation, not a specific pairing).
    - `netLegs : [Instruction] -> [Instruction]` — collapse to ONE net Instruction per
      `(party, instrument)`: `netAmount(party, inst) = Σ receives − Σ delivers`; a positive net is a
      receive (sender = a settlement counterparty / custodian), a negative net is a deliver. Default
      ON. Keep the gross list available (do not mutate it).
    - `conservationOk : [Instruction] -> [InstrumentId] -> Bool` — for every instrument,
      `Σ delivered == Σ received` (and net over parties == 0). This is the fail-loud predicate the
      Round.Clear rewrite (11-05) will `assertMsg` on.

    Ledger helper: `settleBatch : Party -> [Instruction] -> [(Party, InstrumentId, ContractId Holding)]
    -> Update ()` — given the custodian + the (netted) instructions + the source Holding cids per
    (owner, instrument), execute each leg as a `moveExactHolding` (Holding transfer) IN THE ONE
    calling transaction. All-or-nothing: any failing leg rolls back the whole Update. Do NOT open
    separate transactions or sequence commits. Directive prose only; no fenced code in this action.

    §4 pure-reduction check (Pitfall 6): with A as the sole buyer, `buildGrossInstructions` +
    `netLegs` must reproduce A↔B 8@100 / A↔C 2@100 at $100.00.
  </action>
  <acceptance_criteria>
    - `Settlement.daml` exports `Instruction`, `buildGrossInstructions`, `netLegs`, `conservationOk`, `settleBatch`.
    - `netLegs` produces exactly one Instruction per `(party, instrument)`; `conservationOk` returns True for a balanced batch.
    - `settleBatch` performs all transfers in a single Update (no sequenced commits).
    - `cd daml && daml build` succeeds.
  </acceptance_criteria>
