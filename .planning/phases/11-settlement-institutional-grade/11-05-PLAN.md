<objective>
The settlement-core migration — the coupled change that retires operator-custody `Asset` from the
live path and turns the single-buyer MVP into a production-grade, compliance-gated, token-agnostic,
multi-party atomic settlement, WITHOUT breaking the §4 canary. Rewrite `Round.Clear` to settle via
the Settlement Batch/Instruction flow (11-04) from the verified allocation; delete the
single-funded-buyer guard; add per-instrument conservation asserts; take a `cashInstrument`
`InstrumentId` (DFIN-03); wire the on-ledger `DeskEligibility` gate (COMP-01) at Order creation +
commit + Holding issuance; migrate the Phase-10 bond from `Asset` to a cash `Holding`; migrate the
§4 seed + tests to Holdings.

Purpose: DFIN-01 (Batch/Instruction finality retiring Asset) + DFIN-02 (multi-buyer + conservation)
+ DFIN-03 (token-agnostic cash) + COMP-01 (on-ledger eligibility gate).

clears $100.00 / A=10 · B=8 · C=2 and settles atomically. This is the phase's heaviest plan — the
Round.Clear signature change couples Auction ⇄ Roles ⇄ Setup ⇄ Tests, so they migrate together (a
split would leave `daml build` broken between plans).
