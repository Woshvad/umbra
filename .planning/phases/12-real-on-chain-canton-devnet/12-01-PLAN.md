> **Authored inline by the orchestrator during a transient claude-opus-4-8 classifier outage that gated Agent/Bash (the gsd-planner could not be spawned). ## Objective

Insert a REAL, on-ledger four-eyes control on the settlement path: a `ClearingApproval` (signatory `operator, compliance`) that `Round.Clear` REQUIRES before it settles the Batch. A settle with no / wrong-price / wrong-round / operator-self-made approval aborts on-ledger. This is **additive** — the §8 recompute-and-assert backstop, the Phase-11 CN-Token-Standard Batch/Instruction DvP settlement, and the clearing MATH stay byte-unchanged; a new authority precondition is inserted. **The §4 canary still clears $100.00 / A=10·B=8·C=2** with the approval threaded.

This is the phase's correctness-critical, COUPLED plan (Approval ⇄ Round.Clear signature ⇄ Setup seed ⇄ every Tests.daml `Clear with …` call site ⇄ regenerated `web/daml.js`). Like 11-05, it is ONE plan so `daml build` never breaks between commits.

## Must-haves (goal-backward)

1. `daml/Umbra/Approval.daml` defines `ClearingApprovalRequest` (signatory operator, observer compliance) + `ClearingApproval` (signatory operator, compliance) + `assertClearingApproved`, mirroring `Compliance.daml`'s `DeskEligibility` shape. NO contract keys (LF 2.1 — D7/11-02): thread by ContractId.
2. `Round.Clear` gains ONE additive field `approvalCid : ContractId ClearingApproval` and, immediately after `let priceDec = roundBankers 2 clearingPrice` (before `buildGrossInstructions`), fetches it and asserts it matches this operator/round and the recomputed price.
3. `daml build` green and `daml test` exit 0 with the §4 canary intact: `test_four_eyes_clears_at_100` clears **$100.00 / A=10·B=8·C=2** and settles atomically; all pre-existing tests still pass.
4. Negative tests pass (all via `submitMustFail`): `test_settle_without_approval_rejected`, `test_settle_wrong_approval_rejected` (wrong price and/or wrong round), `test_operator_cannot_self_approve` (operator alone cannot bring a `ClearingApproval` into being).
5. `web/daml.js` regenerated (`daml codegen js`) and committed so the additive templates + the new `approvalCid` field surface in the TS bindings (fresh-clone invariant; the rebuilt DAR's package hash changed).
