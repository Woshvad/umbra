# Plan 12-02 — OIDC dual-mode auth (IDEN-01/02) + four-eyes solver wiring (IDEN-03)

> **Authored inline by the orchestrator during a transient claude-opus-4-8 classifier outage (gsd-planner could not be spawned). Grounded verbatim in 12-RESEARCH.md Patterns 2/3 + Code Examples. Plan-checker-validated when the classifier recovers.**

## Objective

Replace the unsafe HMAC path with real OIDC on the DevNet/prod path while KEEPING the LocalNet unsafe-HMAC dev loop working (dual-mode). Solver acquires a token via **client-credentials** and verifies RS256 tokens via **JWKS** (`jose`); web desks log in via **auth-code + PKCE** (`oidc-client-ts`) with a dev-token fallback. Secrets stay server-side; the web bundle is secret-less. Also wire the solver's four-eyes **approval request/collect** step (from 12-01) into the settle path. Every live token exchange is offline-mocked here; live exchange against a booted Keycloak + Canton = UAT.

## Must-haves

1. `solver/src/auth.ts` exports `acquireToken()` (client-credentials form-POST to `${OIDC_ISSUER}/protocol/openid-connect/token`) and `verifyToken(token)` (`jose` `createRemoteJWKSet` + `jwtVerify` pinned RS256, `audience: https://canton.network.global`).
2. Dual-mode: `solver/src/ledger.ts` `resolveOperator()` grows a mode switch — dev reads `scripts/.operator-token` (HS256, unchanged); OIDC calls `acquireToken()`. Selected by env (e.g. `OIDC_ISSUER` set → OIDC; unset → dev HMAC). The existing solver tests stay green.
3. `solver/src/auth.test.ts` (vitest, offline): generate an RS256 keypair via `jose.generateKeyPair('RS256')`, serve a local JWKS + a mock `/token`; assert `acquireToken()` returns the minted token, and `verifyToken()` ACCEPTS a correct-audience token and REJECTS wrong-audience / wrong-key / expired.
4. `web/src/auth/oidc.ts` builds an `oidc-client-ts` `UserManager` (authority `VITE_OIDC_AUTHORITY`, `client_id: 'umbra-web'` PUBLIC, `response_type: 'code'` PKCE, `scope: 'openid daml_ledger_api'`, redirect `${origin}/callback`); DUAL-MODE — if `VITE_OIDC_AUTHORITY` is unset, fall back to the dev token in `tokens.json` (unchanged). NO client secret in the web module.
5. A web test asserts the PKCE authorize config (response_type=code, no client_secret key) AND greps the built bundle / source to assert the OIDC client secret string is ABSENT (secret-less public client).
6. `.env.example` gains placeholder `OIDC_ISSUER` / `OIDC_JWKS_URL` / `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` (server-side, gitignored — placeholders only) and `web/.env.example` gains `VITE_OIDC_AUTHORITY` (public). None reach a committed secret.
7. Solver four-eyes wiring: after computing + deterministically re-verifying §8, the solver (operator) creates a `ClearingApprovalRequest` at the recomputed price, the compliance path exercises `ApproveClearing`, and the solver passes the resulting `approvalCid` into `Round.Clear` (mirrors how it already gathers `orderCids`). Offline-tested with the mocked v2 ledger.
8. `cd solver && npx vitest run` and `cd web && npm run build` + `npx vitest run` all green.
