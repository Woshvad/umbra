# Plan 12-03 — Keycloak realm + TLS + Canton OIDC config (IDEN-01/02)

> **Authored inline by the orchestrator during a transient classifier outage (gsd-planner unavailable). Grounded in 12-RESEARCH.md Pattern 3 + the official Keycloak-for-Canton guide cited there. Plan-checker-validated when the classifier recovers.**

## Objective

Ship the identity-provider artifacts the OIDC dual-mode path (12-02) needs: a Keycloak realm export, a docker-compose to run it, a Caddy dev-TLS reverse proxy, and the Canton participant auth-config that trusts the Keycloak issuer (`jwt-jwks`) with the SAME audience `https://canton.network.global` — as a dual-mode artifact (the LocalNet `unsafe-jwt-hmac-256` path stays for dev). These run at UAT (needs Docker); their SHAPE is asserted offline by a realm-shape test.

## Must-haves

1. `deploy/keycloak/umbra-realm.json` — realm `umbra` with: confidential client `umbra-solver` (service accounts / client-credentials, default scope `daml_ledger_api`), public client `umbra-web` (standard flow auth-code + PKCE, redirect URIs to the web origin, scopes `openid` + `daml_ledger_api`), a `daml_ledger_api` client scope with an **Audience mapper → `https://canton.network.global`** + a User-Client-Role mapper, realm roles **Trader / Compliance / Admin**, users `bankA/bankB/bankC/guest → Trader`, a `compliance → Compliance`, an `admin → Admin`, and an **OTP required-action / conditional bound to Compliance + Admin** (MFA on settlement-affecting roles).
2. `deploy/keycloak/docker-compose.yaml` — Keycloak (`quay.io/keycloak/keycloak`, realm import from the committed JSON) + its Postgres + the Caddy TLS proxy.
3. `deploy/keycloak/Caddyfile` — dev TLS (`tls internal`) reverse-proxying to Keycloak (JWKS at `/realms/umbra/protocol/openid-connect/certs`).
4. `deploy/canton/participant-oidc-auth.conf` — a HOCON artifact setting `ledger-api.auth-services = [{ type = jwt-jwks, url = <JWKS URL>, target-audience = https://canton.network.global }]` (exactly one of target-audience/target-scope — audience), with an honest header that DEV keeps `unsafe-jwt-hmac-256` (dual-mode).
5. `deploy/keycloak/realm.test.mjs` — an offline Node test asserting the realm JSON shape: the two clients (with correct flow flags — solver serviceAccountsEnabled true / publicClient false; web publicClient true + standardFlowEnabled + PKCE), the three roles, the audience mapper value `https://canton.network.global`, and OTP on Compliance/Admin. No Docker needed.
6. `deploy/README.md` — how to boot Keycloak, import the realm, and point the solver/web `.env` at it (the audience/JWKS URL wiring), with the honest "live token exchange is UAT" note.
