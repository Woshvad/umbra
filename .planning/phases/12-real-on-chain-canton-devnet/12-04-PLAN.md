# Plan 12-04 — DevNet connection + ops artifacts + runbook (CHAIN-01/02/03)

> **Authored inline by the orchestrator during a transient classifier outage (gsd-planner unavailable). Grounded in 12-RESEARCH.md Q4/Q5, the Splice compose/onboarding docs cited there, and Pitfalls 3–7. Plan-checker-validated when the classifier recovers.**

## Objective

Build every OFFLINE artifact for taking Umbra onto the real Canton DevNet — the Splice self-hosted validator compose (parameterized), a `devnet-deploy.mjs` that uploads+vets the frozen DAR and allocates parties (mirroring `scripts/localnet/deploy.mjs`), the ops layer (per-network Postgres, `pg_dump` backup, monitoring, Canton-Coin traffic auto-top-up config), and the human-executable `RUNBOOK.md` + `SV-SPONSOR-CHECKLIST.md`. **The live SV-sponsored connection, live DAR-vet-on-DevNet, live §4-on-real-Canton, and unattended-live-ops are a clearly-labeled EXTERNAL GATE + live UAT — never faked.**

## Must-haves

1. `deploy/devnet/validator-compose/` — a Splice validator docker-compose + `.env.example` exposing every required var as a parameter: `SPONSOR_SV_URL`, `ONBOARDING_SECRET`, `MIGRATION_ID`, `PARTY_HINT=umbra-operator-1` (namespaced format — Pitfall 7), `AUTH_URL`, `AUTH_JWKS_URL`, `LEDGER_API_AUTH_AUDIENCE=https://canton.network.global`, `LEDGER_API_AUTH_SCOPE`, `LEDGER_API_ADMIN_USER`, `VALIDATOR_AUTH_CLIENT_ID`, `VALIDATOR_AUTH_CLIENT_SECRET`, `TARGET_TRAFFIC_THROUGHPUT`, `MIN_TRAFFIC_TOPUP_INTERVAL`. Honest header: run AT THE GATE; never faked offline.
2. `deploy/devnet/devnet-deploy.mjs` — parameterized (JSON_API_URL/auth) DAR upload + **vet** + party-alloc (namespaced hint), mirroring `scripts/localnet/deploy.mjs`; runs the `grantRights` step so the admin user (== token `sub`) holds the operator's actAs/readAs (Pitfall 3). Node `--check` clean; a mocked-v2 test proves the request shapes.
3. `deploy/devnet/devnet-deploy.test.mjs` (or a vitest) — mocked JSON Ledger API v2 asserting the upload/vet/party-alloc/grantRights calls are well-formed (mirror `solver/src/api.test.ts` stubbing). Offline.
4. `deploy/devnet/postgres/docker-compose.yaml` — an isolated per-network Postgres (dedicated volume + non-colliding port) for the participant/validator store.
5. `deploy/devnet/backup/pg-dump.sh` — a scheduled `pg_dump` backup script (env-driven DB creds, timestamped dumps, retention note). `bash -n` clean.
6. `deploy/devnet/monitoring/prometheus.yml` — a scrape config + a documented `/readyz`+`/livez` health-probe expectation.
7. `deploy/devnet/traffic-topup.env.example` — `TARGET_TRAFFIC_THROUGHPUT` + `MIN_TRAFFIC_TOPUP_INTERVAL` (DevNet auto-taps coin — documented).
8. `deploy/RUNBOOK.md` — the end-to-end ops runbook: obtain sponsorship → boot validator → vet DAR → allocate parties + grantRights → run §4 → backup/monitor/top-up. Encodes Pitfalls 3–7 as ordered steps.
9. `deploy/SV-SPONSOR-CHECKLIST.md` — the external outreach checklist: static egress IP → send to sponsoring SV → wait for allowlist adoption (2–7 days) → sponsor URL → JIT onboarding secret (1h/48h, one-time). Front-loads the days–weeks lead time (ROADMAP "start immediately").
