## Objective

Give the four-eyes gate (12-01/12-02) a minimal on-screen control: on the Operator/Theatre plane, surface the PENDING clearing price awaiting Compliance sign-off, with **APPROVE** / **REJECT** actions that call the solver's approval request/collect endpoint. This makes the four-eyes separation visible in the demo; the real human-Compliance live approval against a booted stack is UAT.

## Must-haves

1. `web/src/components/ComplianceApproval.tsx` — a control that shows the pending round's recomputed clearing price and an APPROVE / REJECT pair, bound to the comp tokens (paper/ink/lime + red for reject; IBM Plex Mono for the price; reuse the existing button/tag grammar — NO invented visual language). Shows a clear "COMPLIANCE — FOUR-EYES" label and, on the dev path, an honest "DEV COMPLIANCE PARTY — LIVE HUMAN FOUR-EYES AT UAT" micro-label.
2. `web/src/solver.ts` — a client method (`approveClearing`/`rejectClearing`) hitting the solver's four-eyes endpoint (from 12-02), decode-safe.
3. `web/src/views/TheatreView.tsx` — mount the control on the operator plane, gated to the pending state; APPROVE unblocks settle, REJECT blocks it (surfacing the on-ledger reject verbatim if a settle is attempted without approval).
4. `cd web && npm run build` + `npx vitest run` green; views 01–07 otherwise unaffected; §4 still renders $100.00 in the settlement flow (with the approval step).
