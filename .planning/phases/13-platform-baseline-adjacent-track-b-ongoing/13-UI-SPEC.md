# Phase 13 — UI Design Contract

> Visual and interaction contract for the frontend surfaces of Phase 13 (Platform Baseline & Adjacent). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note (read first):** Phase 13 is ~80% backend (OTel, vault, idempotency, FSM, webhooks, sandbox, FIX). Those have **NO UI** — do not invent any. This contract covers **exactly four** frontend surfaces and no more:

| # | Surface | Req | Placement | Priority |
|---|---------|-----|-----------|----------|
| S1 | Public Status Page | OPS-02 | Standalone, solver-served `GET /status.html` — OUTSIDE the React app, token-free | **Primary — build** |
| S2 | Competing-Solvers Leaderboard | ADJ-01 | Additive panel on **Agent view (04)**, below the existing proposal/rationale grid | Build |
| S3 | RFQ side-mode panel | ADJ-02 | Additive panel on **Desk view (02)**, below the OrderTicket | Build |
| S4 | Issuance / Coupon panel | ADJ-03 | **OPTIONAL** additive panel on **Theatre view (03)**; may be folded/deferred | Optional — minimal |

No new nav tab is introduced (per CONTEXT bias: additive panels + one standalone public page). The existing 7-tab `Nav.tsx` is unchanged. The status page is a self-contained HTML/CSS document, not a React view.

## Spacing Scale

The binding comp uses an **irregular literal set**, not a pure 8-point scale. This is a documented, binding exception (CLAUDE.md rule 2 — the comp overrides the default 8-point recommendation). Reuse the tokens already declared in `web/tailwind.config.ts`; do not add new spacing values.

| Token | Value | Usage in Phase 13 surfaces |
|-------|-------|----------|
| `11` | 11px | Tag/dot gaps, badge horizontal rhythm |
| `14` | 14px | Row padding (leaderboard/quote rows, `14px 0`) |
| `18` | 18px | Compact block padding |
| `22` | 22px | Panel inner gaps |
| `26` | 26px | Panel top padding (`26px 40px 0 0` established) |
| `30` / `34` / `42` | 30/34/42px | Section separations |
| `48` | 48px | View gutter (`padding: 0 48px`, matches Nav) |
| `64` | 64px | Major section break |
| Tailwind default 4-scale | 4/8/16/24/32 | Available; prefer the comp literals above for parity with existing panels |

**Exceptions:** The irregular literal set itself is the exception (comp-binding). Badge padding is the established `3px 7px` (mono 9px tag). No touch-target exception needed — all Phase 13 surfaces are desktop demo/ops screens.

## Typography

Declared roles for the four surfaces, each mapped to an **existing** `fontSize` token (no new tokens). Weights are the established three: 400 regular, 600 semibold, 700 bold. Data/numerals always use `font-mono` + `tabular-nums`.

| Role | Token / Size | Family | Weight | Line Height | Used by |
|------|------|--------|--------|-------------|---------|
| Field label / tag | `9` (9px) / `10` (10px) | Inter (body) / IBM Plex Mono (tag) | 400 / 600 | 1 / 1.2 | All — uppercase labels (`.14em`), honest-label tags (`.12em`) |
| Body / status value | `13` (13px) | Inter (body) or IBM Plex Mono (data) | 400 body / 600 data | 1.6 / 1.4 | Status page rows, quote/leaderboard row labels |
| Data numeral (row) | `15` (15px) | IBM Plex Mono | 600 | 1 | Signed fills, matched-volume, surplus, quote price |
| Proposal / metric value | `22` (22px) | IBM Plex Mono | 700 | 1 | Status "LAST CLEAR" price, issuance clear metric |
| Money-shot clear price | `120` (120px) hero **only where the reveal is reused** (S4 issuance) | IBM Plex Mono | 700 | .9 | S4 issuance uniform-price reveal (reuses `PriceReveal`) |

**Status-page headline (S1):** display wordmark uses `30` (30px, Space Grotesk, 700, `.tight` `-.02em`) — identical to the app `UMBRA` wordmark. Section headings on panels use Inter 13px/600 `.04em` uppercase, matching `Nav`/`StatusIndicator`.

## Color

60 / 30 / 10 split is the established comp discipline — unchanged for Phase 13.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F1EA` paper | Page/panel background — status page body, all four panels |
| Secondary (30%) | `#0A0A0A` ink | All 1px borders, body/data text, tags, redaction surfaces (`#262626` redact for stripe motif) |
| Accent (10%) | `#D6FB3C` lime | **Reserved — see list below** |
| Destructive / signal | `#E2231A` red | Status DOWN/DEGRADED pill, UNVERIFIED solver badge, RFQ reject copy, active nav rule |

**Accent (lime) reserved for — explicit list (never "all interactive elements"):**
- The **money-shot clearing price** only: the S4 issuance uniform-price reveal numeral (reuses `PriceReveal`'s lime hero slab).
- The S1 status page "OPERATIONAL" health state MAY use a **lime dot** (11px) as the up indicator — this is the single health-accent use, consistent with lime = "the clear succeeded / venue healthy". Lime is NOT used for text on the status page.
- **Nowhere on S2 (leaderboard) or S3 (RFQ)** — those use ink for verified/data and red for unverified/reject. The leaderboard "winner" is marked with ink weight/rule, not lime, because the winner is narrative — only the authoritative deterministic clear earns any celebratory treatment.

Supporting data colors (already declared, not new): Buy `#2B3AF2`, Sell `#FF3D9A` for signed fills; `#FF6A1A` flame reserved to Theatre/Agent solver dots only. `rgba(10,10,10,.16)` row rules, `rgba(10,10,10,.4/.5/.6)` muted text — all established.

## Surface Inventory

### S1 — Public Status Page (OPS-02) — PRIMARY

**What it is:** A standalone, **token-free**, solver-served health page at `GET /status.html`, reading `GET /status` (JSON). Deliberately SEPARATE from the authenticated 7-view app. Exposes **zero** private order data — aggregate/health only.

**Implementation form:** A small **self-contained HTML/CSS document** served by the solver (no React, no Tailwind build, no `@daml/react` context, no auth). Because it has no build step, it **inlines the brand tokens as literal CSS** in a `<style>` block: `background:#F4F1EA; color:#0A0A0A;` , the lime `#D6FB3C` up-dot, red `#E2231A` down state, and `@import`/`<link>` Google Fonts for Space Grotesk + IBM Plex Mono (with `system-ui`/`monospace` fallbacks so it renders offline). It must be visually consistent with the app header (same `UMBRA` wordmark at 30px Space Grotesk `-.02em`).

**Data shown (aggregate/health ONLY — from `GET /status`):**
- Venue up/down (health pill + dot)
- Current round **phase** (Open / Sealed / Cleared / Settled) — phase name only, never order contents
- **Last clear price + timestamp** (e.g. `$100.00 @ 14:32:07 UTC`) — the aggregate uniform price is public by design
- Uptime
- Build / version string

**MUST NOT show:** any individual order, desk identity, per-desk fill, bid/limit, sealed-order contents, token, or operator identifier. If in doubt, omit.

**States:**
| State | Rendering |
|-------|-----------|
| Operational | Lime `#D6FB3C` 11px dot + `OPERATIONAL` (ink 13px/600 mono). All metrics populated. |
| Degraded | Red `#E2231A` dot + `DEGRADED` — health endpoint reachable but a check is failing. |
| Offline | Red dot + `OFFLINE` — solver reports down. |
| No active round (empty) | Metrics grid shows phase = `— IDLE`; heading `NO ACTIVE ROUND`, body "Venue idle — waiting for the next round to open." Last-clear row persists if a prior clear exists. |
| Feed unreachable (client can't fetch `/status`) | Full-page notice `STATUS UNAVAILABLE — cannot reach the venue. Retrying…`; auto-refresh poll continues. |

**Layout:** paper page, centered column, 1px-ink bordered metric rows (label left = Inter 10px `.14em` uppercase opacity .5; value right = IBM Plex Mono 22px/700 tabular-nums), persistent honest-label tag `PUBLIC HEALTH · NO PRIVATE ORDER DATA` in the header. Auto-refresh (poll `/status` on an interval; reduced-motion friendly — no animation required).

**Copy:** heading `UMBRA VENUE STATUS`; pill `OPERATIONAL` / `DEGRADED` / `OFFLINE`; rows `PHASE`, `LAST CLEAR`, `UPTIME`, `BUILD`.

### S2 — Competing-Solvers Leaderboard (ADJ-01)

**What it is:** An **additive** panel on the Agent view (04), mounted BELOW the existing `AgentProposal` / `AgentRationale` grid (and above/below `BreakTheAiPanel` — keep it a distinct block). It ranks the N solver proposals by **(matched volume ↓, surplus ↓)**, tags each **VERIFIED / UNVERIFIED** against the deterministic §8 recompute, and clearly marks the deterministic clear as the **authoritative settle**. It is a **narrative leaderboard, not a settlement input**.

**Component:** new `web/src/components/SolverLeaderboard.tsx` (operator-plane display only — reads a lifted response from `web/src/solver.ts`; **no** operator token, **no** `@daml/react` context — same discipline as `AgentProposal`).

**Row contract (1px ink top, rows `border-bottom rgba(10,10,10,.16)`, `14px 0` padding):**
- Rank numeral (mono 11px/600 opacity .6, zero-padded)
- Solver config tag (mono 9px `.12em` ink border — e.g. `HAIKU · t0.0`, `SONNET · t0.4`) — model/temp, honest
- Matched volume (mono 15px/600 tabular-nums)
- Surplus (mono 15px/600 tabular-nums)
- **VERIFIED** badge (ink text, reuse `AgentProposal` badge styling — mono 9px `.12em` border) when the proposal **equals** the deterministic result; **UNVERIFIED** badge in red `#E2231A` when it diverged.

**Authoritative marker:** A distinct, always-present block — `DETERMINISTIC §8 CLEAR — AUTHORITATIVE` (ink, mono 9px tag) — visually separated (e.g. a heavier 1px-ink top rule or a labeled sub-header) from the ranked list, restating the clearing price/matched that will actually settle. The narrative "winner" (rank 1 among verified) is marked with **ink weight / a rule**, never lime (lime is reserved to the true clear).

**States:** empty (`NO COMPETING PROPOSALS YET` + body); loading (reuse `animate-umbra-pulse` `COMPUTING` idiom from Theatre); offline (reuse `OFFLINE_CAPTION`); ranked (list). Persistent honest tag: `LEADERBOARD · NARRATIVE — NOT A SETTLEMENT INPUT`.

### S3 — RFQ side-mode panel (ADJ-02)

**What it is:** A **minimal additive** panel on the Desk view (02), below `OrderTicket`. Flow: post an RFQ (instrument / side / qty) → see one or more **signed firm quotes** → **accept the best** → it settles via the **same atomic Canton DvP path**, reusing the existing settlement visuals (`DvpLegs` + `AtomicStamp`). Single bond, firm quotes, no streaming.

**Component:** new `web/src/components/RfqPanel.tsx` (desk-plane — submits on the desk's OWN token, grep-clean of operator token / `@daml/react` / Anthropic key, matching `OrderTicket`).

**Flow states:**
| State | Rendering |
|-------|-----------|
| Idle / compose | Instrument (fixed `BONDX` label), Side toggle (Buy `#2B3AF2` / Sell `#FF3D9A` — reuse `OrderTicket` toggle), Qty input (mono). CTA **`REQUEST QUOTE`** (ink-fill primary, matching the established primary-button treatment). |
| Posted / awaiting | `AWAITING QUOTES…` caption (reduced-motion friendly pulse). |
| Quotes in | List of firm quotes, each row: dealer id (mono), price (mono 15px/600 tabular-nums), tag `FIRM · SIGNED` (ink border tag). **Best quote** highlighted with a 1px-ink emphasis + `BEST` marker. CTA **`ACCEPT BEST QUOTE`** (single confirm, no dialog). |
| Settling / settled | Reuse `DvpLegs` (the 1×1 batch draw-on) + `AtomicStamp` — no new settlement grammar. Show `SETTLED · ATOMIC` via the existing stamp. |
| Empty | `NO QUOTES YET` + body. |
| Error / offline | Reuse `OFFLINE_CAPTION`; reject copy rendered verbatim on an ink evidence surface (matching `BreakTheAiPanel` verbatim-reject convention). |

**Honesty:** RFQ is a 1×1 DvP that **reuses** the same `Settlement`/`Round.Clear` atomic machinery — do not imply a separate settlement engine.

### S4 — Issuance / Coupon panel (ADJ-03) — OPTIONAL / MINIMAL

**What it is:** An **optional**, compact additive panel. If warranted, it shows a **primary-issuance uniform-price clear** (reusing the crossing/reveal visuals) and a **coupon / redemption lifecycle row**. Keep it minimal; the executor MAY fold it into an existing view or defer it if plan scope is tight.

**Placement:** Theatre view (03), because it reuses `CrossingChart` + `PriceReveal` which already live there. A single compact block; do not add a nav tab.

**Component (if built):** new `web/src/components/IssuancePanel.tsx` — reuses `CrossingChart` (issuance supply/demand crossing) and `PriceReveal` (the uniform issuance price — this is the one place lime is allowed, as it IS a real uniform-price clear reveal), plus a compact `LifecycleRow` for `COUPON PAID` / `REDEEMED` states (ink rows, mono values, `LIFECYCLE` tag).

**States:** pre-clear (assembling — reuse `CrossingChart` `mode="assembling"`); cleared (reveal + minted-holdings summary); lifecycle (coupon paid pro-rata / redemption retired). Tag: `PRIMARY ISSUANCE · UNIFORM-PRICE`.

**If deferred:** record the deferral in the plan; no partial UI. This surface is explicitly droppable without failing the phase's UI contract.
