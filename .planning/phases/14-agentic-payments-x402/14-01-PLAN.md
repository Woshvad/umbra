<objective>
Create the hand-rolled, dependency-free x402 payment gate for the Umbra solver: the x402 **v1** HTTP wire envelope (pinned verbatim in 14-RESEARCH.md) plus a factory middleware that mirrors `idempotency.ts`. This is the PAY-01 core — the HTTP-402 negotiation surface that a real x402 client can pay byte-faithfully — with settlement delegated to an injected `FacilitatorClient` (implemented in Plan 02) so this module carries zero ledger/secret concerns.

Purpose: Deliver the 402 signalling + `accepts[]` envelope + `X-PAYMENT` decode + replay guard as a single, fully unit-tested, secret-safe module, with the **default-OFF no-op** as the primary invariant. Everything downstream (facilitator backends, boot wiring, config) builds against the interface this plan defines.

Output: `solver/src/x402.ts` (wire types, zod schema, pure envelope helpers, the `FacilitatorClient` interface, the `PaymentGate` factory) and `solver/src/x402.test.ts`. Zero new npm packages (express + node:crypto + Buffer + zod, all in-tree).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| x402 client → solver gate | Untrusted `X-PAYMENT` header (base64-JSON) crosses into the gate; every field is attacker-controlled |
| gate → wrapped AI handler | The gate must fully authorize before `next()` — the AI never degrades to reject, so blocking happens at the HTTP layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Spoofing/Elevation | X-PAYMENT replay (resend a valid payload) | mitigate | Module-private spent-nonce `Set` (TTL-bounded) + `validBefore` expiry check in `x402Gate`; reject `nonce_replayed` / `payment_expired` |
| T-14-02 | Tampering | Double-use of a presented fee-Holding cid | mitigate | Module-private spent-`holdingCid` `Set` recorded on successful settle; a reused cid → 402 (ledger archive is the backstop, Plan 02) |
| T-14-03 | Information Disclosure | Secret leaking into a 402 body / X-PAYMENT-RESPONSE / raw throw | mitigate | All emits route through `send402` with authored secret-free reasons; the gate never throws raw; secret-sweep test asserts an X402_FACILITATOR_KEY sentinel absent from every body/header |
| T-14-04 | DoS/Tampering | Malformed / oversized X-PAYMENT | mitigate | `paymentPayloadSchema` zod `.strict()` + bounded string lengths + a base64 header length bound in `decodePayment`; failure → secret-free `invalid_payload` |
| T-14-05 | Tampering | Default-OFF gate perturbs the money-shot demo | mitigate | `if (!opts.enabled) return next()` as the first handler line; `off unchanged` test asserts byte-identical responses |
| T-14-SC | Tampering | npm supply chain | accept | Zero new packages installed this phase (14-RESEARCH.md Package Legitimacy Audit — `x402-express` rejected as EVM/Solana-oriented); nothing added to package.json |
</threat_model>
