<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gate → facilitator | The gate hands attacker-influenced `PaymentPayload` (holdingCid, from) to verify/settle — the fee-source must be authorized on-ledger, not assumed |
| solver → Canton JSON Ledger API v2 (self) | Operator-authority exercise crosses to the participant; the operator bearer stays in the Authorization header only |
| solver → FTP facilitator (canton-cc) | Outbound `/verify`+`/settle` over fetch; the facilitator key rides one request header |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-06 | Tampering | Insufficient / wrong-instrument / wrong-owner / locked fee Holding | mitigate | `self.verify` predicate: `owner===payer` + `instrumentId==='USDCx'` + `!locked` + `amount ≥ fromAtomic(price)` (the `gatherHoldingCids` predicate), reason ∈ {invalid_holding, wrong_instrument, amount_too_low} |
| T-14-07 | Tampering | Double-settle of the same fee Holding cid | mitigate | Ledger archives the presented cid on `moveFee` (Reassign/Split), so a re-verify against the stale cid fails naturally; the gate's spent-cid set (Plan 01) is the HTTP-layer backstop |
| T-14-08 | Information Disclosure | Facilitator key exposure (canton-cc) | mitigate | `facilitatorKey` rides only the `Authorization` header, held module-private, never returned in a result / logged / echoed; non-2xx → status-only throw (secrets.ts:65-69 precedent); secret-sweep test |
| T-14-09 | Information Disclosure | Operator bearer / raw ledger error text leaking through settle | mitigate | `moveFee` uses the existing module-private operator bearer (ledger.ts); errors collapse to secret-free reasons; the txRef is a synthetic secret-free ref |
| T-14-10 | Tampering | Fee transfer leaking onto the securities DvP path | mitigate | `moveFee` is a standalone single-Holding operator move to the venue — it never calls `settle`/`Round.Clear`; §8 stays the sole settlement authority; `settle`/`tamperClear` byte-unchanged |
| T-14-SC | Tampering | npm supply chain | accept | Zero new packages (14-RESEARCH.md Package Legitimacy Audit); `@cantrustai/x402` does not exist → self-implemented adapter to the generic HTTP contract |
</threat_model>
